# Claude Code — контекст проекта microchips-next-site

## 1. Проект и стек

SEO/каталог-миграция для microchips.by — B2B промышленные аккумуляторы и ИБП.
Мультистрановая платформа: frontend Next.js (`frontend/`) + backend Laravel
(`backend/`). Первый рыночный фокус — Беларусь (RB). Репо:
`github.com/aidzmitry-gif/microchips-next-site`, главная ветка `main`, рабочие
ветки `codex/*`. В репо параллельно работают Claude- и Codex-сессии.

## 2. Карта проекта

Ключевые скрипты (`scripts/`):
- `verify-rb-prototype.ps1` — статический гейт для `docs/prototypes/rb-b2b-*.html`: noindex+nofollow, отсутствие внешних ресурсов и fetch/XHR, ровно один `<h1>`, контракт lead-формы против `LeadController`.
- `extract-bitrix-b2b-catalog-slice.ps1` — read-only извлечение из бэкапа Bitrix SQL gzip; флаги `-RunSelfTest`, `-WhatIf`; ничего не пишет в источник.
- `build-rb-import-manifest.ps1` — строит `docs/audits/generated/rb-import-manifest-draft.csv` (1569 строк фокуса), извлекает brand/mpn (~99% авто), детектит коллизии артикулов; падает при расхождении счётчиков с аудитом.
- `audit-rb-nomenclature.py` — сверяет название товара со свойствами базы Bitrix, ищет 8 классов ошибок; пишет findings CSV + markdown-отчёт (`docs/imports/`) + xlsx (через `build-nomenclature-xlsx.py`).
- `build-nomenclature-xlsx.py` — строит Google-совместимый `.xlsx` из findings.

Где что лежит:
- Генерируемые артефакты — `docs/audits/generated/` (в `.gitignore`, не коммитятся).
- Отчёты-доки — `docs/imports/` и `docs/` (отслеживаются).
- Прототипы — `docs/prototypes/rb-b2b-*.html` (+ ассеты в `docs/prototypes/assets/`, включая логотип `logo-ar-final.png`).
- Backend-контракт lead-формы — `backend/app/Http/Controllers/Api/V1/LeadController.php` (Laravel, тесты PHPUnit, стиль Laravel Pint).

## 3. Конвейер данных

`extract-bitrix-b2b-catalog-slice.ps1` → `build-rb-import-manifest.ps1` →
`audit-rb-nomenclature.py` (→ `build-nomenclature-xlsx.py`).

Правило: сначала фикс в 1С/на сайте, потом свежая выгрузка, потом перегон по
конвейеру заново. Не редактировать сгенерированные артефакты руками — только
через источник.

Блокер идентичности: артикулов/SKU нет нигде в Bitrix (база, живой сайт, все
8 экспортов в полной копии — проверено). Нужен внешний источник (выгрузка 1С
или прайс поставщика). Кандидаты brand+mpn извлечены из кодов моделей в
названиях (99% авто), но не подтверждены → публикация каталога заблокирована
до подтверждения.

## 5. Verify-гейт

Перед тем как считать прототип готовым — прогнать `verify-rb-prototype.ps1`
(без аргументов проверяет все `rb-b2b-*.html`) и добиться зелёного результата.
Находки любых аудитов/экстракторов проверять адверсариально до того, как им
доверять; ложные срабатывания детекторов — чинить, а не игнорировать.
Machine-гейт держит качество, не модель.

## 6. Тиринг моделей

Подробности — `docs/standards/model-tiering.md`. Кратко:

| Тир | Модель | Когда |
|---|---|---|
| 1 | Haiku 4.5 | механика: сканы/чтение/скаффолд/форматирование |
| 2 | Sonnet 5 | ревью/код/порт/тесты/верификация с суждением |
| 3 | Opus 4.8 | деньги/схема-миграции/контракты/адверсариальный судья |

Fable 5 — вне тиринга (флагман, не дефолт; звать точечно, только если Opus
доказанно не тянет). Effort ортогонален модели: low — механика, medium —
обычная задача, high — ревью/деньги-логика, xhigh/max — архитектура/судья.
Сабагенты по умолчанию НЕ наследуют Fable.

## 7. Подводные камни

- **PowerShell 5.1 + кириллица**: скрипты `.ps1` с кириллицей должны быть в
  UTF-8 с BOM, иначе парсер падает («Unexpected token» на кириллице). Лечение:
  прочитать как UTF-8 без BOM, записать как UTF-8 с BOM.
- Пути содержат пробелы и кириллицу — всегда в кавычках.
- `git push`/`commit` только по явной просьбе пользователя. Co-author trailer
  в коммитах.
- Предупреждение Windows «LF will be replaced by CRLF» — норма, не ошибка.
- Блокер артикулов (см. п.3) — не пытаться закрыть публикацию каталога без
  внешнего источника SKU.
