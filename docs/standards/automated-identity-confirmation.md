# Алгоритм безопасного автоподтверждения идентичности

Статус: спецификация к реализации. Дата: 2026-07-26.
Заменяет ручной гейт `docs/standards/launch-policy.md` §3.1 **частично** — только там,
где все перечисленные ниже условия выполнены. Всё остальное по-прежнему уходит человеку.

## Зачем это вообще, если был человеческий гейт

Ручной гейт уже дал сбой на реальных данных. Из 23 подтверждённых человеком пар
**14 несут складской классификатор вместо артикула производителя** — код
`О3.2.52.29.` закреплён в 1С за четырьмя разными товарами (Delta DT 12045,
Delta HRL 12-7.2 и др.), но был подтверждён как уникальный коммерческий SKU.
См. `docs/audits/2026-07-26-approved-identities-quality.md`.

Механика сбоя понятна и воспроизводима: `confirmed_sku` во всех 23 строках —
дословная копия поля `article` из 1С. Человек не сверял, а переносил.

Вывод: «подтверждает человек» само по себе не даёт качества. Качество даёт
**проверка независимыми источниками**, и её как раз можно выполнить механически,
воспроизводимо и без усталости. Задача этого документа — описать такой гейт так,
чтобы он был строго консервативнее среднего человеческого решения.

## Принципы

1. **Никогда — по одному источнику.** Подтверждение только при согласии независимых источников.
2. **Детерминированные правила, не суждение модели.** Каждое подтверждение обязано быть
   объяснимо ID правила и воспроизводимо повторным прогоном. LLM может *готовить* кандидатов,
   но решение принимает код по правилам.
3. **Физическая сверка.** Артикул большинства АКБ кодирует напряжение и ёмкость — это даёт
   независимую проверку смысла, а не только строк.
4. **Консервативный дефолт.** Не проходит хоть один гейт — эскалация человеку. Отказ дёшев,
   ошибка дорога.
5. **Отдельный статус и обратимость.** Автоподтверждение никогда не пишет
   `approved_for_staging`; оно пишет `auto_confirmed` — отличимо, проверяемо, откатывается пачкой.
6. **Никакой публикации.** Автоподтверждение идентичности не публикует товар и не отменяет
   duplicate review. Радиус поражения ограничен.

## Источники (должны быть независимы)

| Код | Источник | Независимость |
| --- | --- | --- |
| S1 | Название номенклатуры 1С | Учётная система |
| S2 | Название товара в Bitrix | Редакторский текст, писался отдельно |
| S3 | Страница товара на живом сайте | Внешний, публично наблюдаемый |
| S4 | Структурные свойства Bitrix (напряжение, ёмкость, бренд) | Отдельные поля, не текст |
| S5 | Каталог/даташит производителя | Внешняя истина вне контура компании |

S1 и S2 считаются независимыми: их заполняли разные люди в разных системах.
S4 независим от S1/S2/S3, потому что это структурированные поля, а не разбор строки.

## Гейты (для автоподтверждения обязаны пройти ВСЕ)

**G1 — Грамматика производителя.** Кандидат соответствует документированной схеме
артикулов этого производителя из реестра грамматик (Delta: `DT|DTM|HR|HRL` + цифры;
Ventura: `GP|GPL` + цифры; CSB: `GP|HR|HRL` + цифры + опц. суффикс `F1|F2|B1`;
CONTACT: `GP` + цифры; Восток: `СК` + цифры). Производитель вне реестра → эскалация.

**G2 — Корроборация.** Минимум **два независимых источника** дают один и тот же
нормализованный идентификатор. Нормализация: регистр, пробелы, дефисы, кириллица↔латиница
в омоглифах (`А/A`, `О/O`, `Р/P`, `С/C`, `Е/E`).

**G3 — Согласие по бренду.** Производитель, выведенный из всех доступных источников,
совпадает. Расхождение (артикул Восток на товаре Ventura) → эскалация.

**G4 — Физическая сверка (ключевой гейт).** Напряжение и ёмкость, закодированные в артикуле,
совпадают со структурными атрибутами товара. Пример: `DT12045` → 12 В / 4.5 Ач; свойства
Bitrix обязаны дать 12 В и 4.5 Ач. Несовпадение → эскалация, даже если строки идентичны.
Этот гейт ловит подавляющее большинство ошибочных сопоставлений, потому что проверяет
физический смысл, а не совпадение текста.

**G5 — Уникальность.** Нормализованный идентификатор не занят другим товаром каталога и
не претендует на него в этой же пачке.

**G6 — Не классификатор.** Идентификатор не соответствует известным шаблонам складских кодов:
`^[А-Яа-яA-Za-z]\d(\.\d+)+\.?$` (точечный) и `^\d+\\[A-Za-zА-Яа-я]\d$` (с обратным слэшем).
Реестр шаблонов пополняется по мере находок.

**G7 — Однозначность связи.** Ровно одна строка 1С соответствует ровно одной строке Bitrix.
Любое «многие-ко-многим» → эскалация.

## Стоп-краны (любой срабатывает — только человек)

| Код | Условие |
| --- | --- |
| K1 | Источники дали разные идентификаторы |
| K2 | Производитель отсутствует в реестре грамматик |
| K3 | G4 не прошёл: напряжение/ёмкость в артикуле не совпали с атрибутами |
| K4 | Идентификатор уже занят другим товаром |
| K5 | Несколько кандидатов претендуют на один идентификатор |
| K6 | Доступен лишь один источник (например живой сайт недоступен, а свойств Bitrix нет) |
| K7 | В названии есть маркеры вариативности без различающего кода: «аналог», «замена», «под заказ» |
| K8 | Товар помечен как дубль или конфликтный в существующей очереди |

## Калибровка — обязательна ДО первого автоподтверждения

Алгоритм не включается, пока не измерена его точность на размеченных данных.

1. **Прогон на 9 строках, где человек был прав** (`DT12012`, `DT1212`, `DT612`, `DT1240`,
   `DT1207`, `DT12032`, `СК12120`, + 2 подтверждённые через MPN). Алгоритм обязан
   воспроизвести их или честно эскалировать. Ни одного расхождения с верным ответом.
2. **Прогон на 14 ошибочных строках.** Алгоритм обязан **не воспроизвести** складские коды.
   Воспроизведение хотя бы одного = алгоритм не готов.
3. **Контроль точности.** На объединённой выборке требуется **100% precision**: ни одного
   ложного подтверждения. Любое ложное срабатывание → алгоритм остаётся выключен,
   правило чинится, калибровка повторяется целиком.
4. Recall не является критерием допуска. Низкая полнота — приемлемая цена; ложное
   подтверждение — нет.

Результат калибровки фиксируется в отчёте с версией правил; при изменении любого правила
калибровка прогоняется заново.

## Предохранители эксплуатации

- **Отдельный статус** `auto_confirmed` (не `approved_for_staging`). В Filament виден отдельно.
- **Полный след:** версия правил, сработавшие гейты, значения источников, точные цитаты, время.
- **Массовый откат** одной командой по версии правил или по пачке.
- **Выборочный контроль:** 10% случайных автоподтверждений выводятся человеку. Обнаружена
  ошибка — вся пачка этой версии правил аннулируется автоматически.
- **Лимит пачки:** не более N строк за прогон (стартово 25), чтобы ошибка не масштабировалась
  до разбора выборки.
- **Публикация не затрагивается:** товар остаётся `is_published=false`, цена и наличие —
  `on_request`. Duplicate review сохраняется как есть.

## Что НЕ автоматизируется никогда

Гейт покрывает **фактические** вопросы — «этот артикул принадлежит этому товару». Он не
покрывает **коммерческие** решения, которые не выводятся из данных:

- нужен ли товар на витрине рынка;
- цена, наличие, сроки;
- юридические и гарантийные формулировки;
- канонический URL и решения по 301;
- разрешение на публикацию.

Эти пункты остаются за владельцем без исключений.

## Ожидаемый эффект на текущих данных

Из 14 проблемных строк алгоритм: заблокировал бы все 14 по G6 (складской шаблон),
а по 12-13 из них смог бы предложить верный артикул через G2+G4 (код модели присутствует
и в названии 1С, и в названии Bitrix, а напряжение с ёмкостью сверяются со свойствами).
Точные цифры проставляются после калибровочного прогона — до него они остаются оценкой.
