# Политика допуска к публикации

Дата фиксации: 2026-07-14. Это единственный нормативный источник для
публикации каталога, SEO/GEO-страниц и страновых витрин. Отчёты, прототипы и
контракты описывают доказательства выполнения правил и ссылаются на этот
документ, но не заменяют его.

## 1. Подтверждённые и site-scoped данные

1. Индексируемая коммерческая страница использует только явно утверждённые
   данные своего `site_id`: товарную видимость, валюту, цену, наличие,
   доставку, оплату, гарантию, контакты, юридическое лицо и региональный
   контент.
2. Цена, остаток, адрес, телефон, реквизиты, сертификат, условия сервиса или
   коммерческая schema-разметка не могут быть выведены из старого сайта,
   crawler-данных, общего каталога или placeholder. До проверки их нет на
   публичной странице.
3. Общий каталог может хранить только проверенную техническую идентичность и
   спецификацию. Его наличие не публикует товар ни в одной стране.

## 2. Прототипы и небоевые артефакты

1. HTML-визуальный прототип — внутренний артефакт согласования: `noindex,
   nofollow`, без canonical и без публикации как маршрут продукта.
2. Placeholder из прототипа нельзя переносить в seed, production-данные,
   SEO-текст, schema или форму как подтверждённый факт.
3. Реальная реализация формы, SSR и metadata обязана соответствовать
   проверяемому API/серверному контракту; визуальный макет сам по себе не
   является контрактом данных.

## 3. Идентичность товара и офферы

1. Исходная строка остаётся `needs_review`, пока для неё не утверждены
   стабильный supplier/1C ID, SKU или MPN, название и категория; дубликаты
   получают явное решение. Автоматическое сопоставление или публикация без
   этих данных запрещены.
2. Импорт обязан учитывать источники товарных офферов. Если связанный
   SKU/offer-источник непустой или его структура не подтверждена, отчёт не
   может объявлять отсутствие артикулов доказанным фактом и не может разрешать
   публикацию.
3. Публикация возможна только после review и отдельного site-scoped решения;
   источник или общий `Product` не создаёт публичный `SiteProduct` сам по
   себе.

## 4. Gate 0 и блокеры запуска страны

**Gate 0 — исходная идентичность.** До следующей инженерной стадии бизнес
передаёт выгрузку 1С или прайс поставщика минимум для 50 товаров утверждённого
фокуса. Для каждой строки нужны источник, стабильный идентификатор,
SKU/MPN (если применим), название и категория; дубликаты и пропуски получают
явный disposition. Gate 0 разрешает только проверку малого staging-среза, а
не публичную публикацию.

Страна не может быть запущена, пока не подтверждены одновременно:

- Gate 0 и прошедший review/import для нужных товаров;
- реальные локальные юридические и коммерческие данные, контакты, валюта,
  доставка, оплата и сервис;
- локальные indexable URL, self-canonical, sitemap/robots, reciprocal
  `hreflang` только для реально опубликованных эквивалентов;
- утверждённый legacy URL manifest и отсутствие блокирующих redirect/SEO
  регрессий;
- отдельные аналитика и верификация Webmaster/Search Console, тестовый лид,
  мониторинг и план отката.

Непройденный пункт является блокером: он не заменяется демонстрационными
данными, документом, частичным кодом или оценкой «почти готово».
