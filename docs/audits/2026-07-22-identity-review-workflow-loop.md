# Инженерный цикл: очередь сверки Bitrix ↔ 1С

Дата: 2026-07-22.

## Результат

Полная номенклатура 1С связана с ранее подготовленной строгой очередью
кандидатов Bitrix ↔ 1С. Очередь не создаёт `products`, `site_products` или
публичные URL. Каждый кандидат требует явного решения администратора и
подтверждённого SKU либо MPN.

Добавлены команды:

```powershell
php artisan catalog:import-identity-candidates "..\docs\imports\rb-1c-review-candidates.csv" --initial-batch=50
php artisan catalog:export-approved-identities "storage\app\approved-identities.csv" --batch=rb-initial-50
```

Первая команда загружает очередь проверки, вторая формирует staging-CSV только
из строк со статусом `approved_for_staging`. Ни одна из них не публикует товары.

## Интерфейс проверки

В Filament добавлен раздел «Сверка Bitrix и 1С». Для каждой пары показаны
названия Bitrix и 1С, код и артикул 1С, метод сопоставления, уверенность, пакет и
статус. Доступны только два явных решения:

- подтвердить идентичность с обязательным SKU или MPN;
- отклонить с обязательной причиной.

Подтверждение блокируется, если нормализованный SKU/MPN уже встречается:

- как SKU или MPN у другого кандидата, включая перекрёстное совпадение;
- как SKU или MPN у уже существующего товара каталога.

## Готовность

Часть 3 «Shared catalog и import core» повышена с 65% до 90%: подтверждены
рабочая функциональность, tests/CI-контур и проверка на полной реальной выгрузке
1С. Последние 10% не начислены: ещё нет воспроизводимого production-deploy и
регламентного ночного обмена.

По общей формуле вклад Части 3 вырос с 9,75 до 13,5 процентного пункта. Общая
подтверждённая готовность системы: **43,8%** (было 40,05%). Страны остаются на
0% до полного завершения частей 1–4, как требует утверждённый гейт.

## Следующий гейт

Человек должен проверить первые 50 пар в Filament, подтвердив реальный SKU/MPN
или отклонив связь. После этого можно экспортировать только подтверждённые строки
в `catalog:stage-1c`, повторно прогнать duplicate review и оставить региональные
товары черновиками. Этот шаг требует бизнес-решения по данным и поэтому не
выполнялся автоматически.
