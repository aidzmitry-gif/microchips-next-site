# Gate 0: почему 50 товаров нельзя получить пакетным подтверждением

Дата: 2026-07-26. Источник: read-only проверка локального PostgreSQL
`microchips-platform` и сверка уже одобренных кандидатов.

## Фактическое состояние

| Статус identity candidates | Количество |
| --- | ---: |
| `approved_for_staging` | 23 |
| `pending` | 85 |
| `rejected` | 1 |

В shared catalog созданы 23 черновых товара и 23 черновых RB `site_products`;
все они непубличны. Открытых `duplicate_conflicts` нет.

## Блокер

Нельзя механически одобрить следующие 27 совпадений по `confidence=0.95`:
часть уже сохранённых `confirmed_sku` — внутренние складские/классификационные
коды 1С, а не MPN производителя. Такое же значение нельзя переносить в новую
строку как коммерческий идентификатор.

Даже если Bitrix и 1С согласны по названию, значение MPN должно быть
подтверждено документацией производителя или поставщика. Иначе Gate 0 будет
формально закрыт, но в каталоге появятся ложные SKU/MPN и риск скрытых дублей.

## Что нужно для безопасного движения

Для 27 новых строк: источник 1С, название Bitrix, точная модель/MPN из
документа производителя или прайса поставщика, производитель, категория и
дата/ссылка на доказательство. Затем решения вносятся через Filament
«Сверка Bitrix и 1С»: `IdentityCandidateReviewer` проверяет уникальность
нормализованного идентификатора и отсутствие совпадения с shared catalog.

После достижения 50 валидных решений требуется экспорт только нового delta,
staging без повторной обработки уже созданных 23 строк, duplicate review и
site-scoped черновики. Публичная публикация этим не разрешается.
