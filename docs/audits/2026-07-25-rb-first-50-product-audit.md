# Аудит товаров первого RB-пакета: категории, URL, атрибуты, описания

Дата: 2026-07-25. Режим: read-only. Ни один товар не опубликован, ни одна
запись источника не изменена.

## Область и метод

Аудируется **первый пакет проверки идентичности (50 позиций)**, внутри которого
находятся 23 подтверждённые человеком пары Bitrix ↔ 1С.

> **Почему 50, а не ровно 23.** Решения ревьюера (`approved_for_staging`,
> `confirmed_sku`/`confirmed_mpn`) хранятся только в таблице
> `catalog_identity_candidates` рабочей БД и в git не попадают: в отслеживаемом
> `docs/imports/rb-1c-review-candidates.csv` все 109 строк остаются
> `review_candidate`, а в шаблоне `rb-first-50-fill-from-1c.xlsx` колонки
> подтверждения пусты. Postgres-контур платформы в этой среде не поднимался
> (тома `microchips-platform_postgres-data` нет). Поэтому аудит покрывает весь
> пакет — так ни одна из 23 позиций не пропущена. Точный список 23 нужно
> выгрузить из Filament-БД (`catalog:export-approved-identities`).

Источники (все воспроизводимые, read-only):

| Данные | Источник |
| --- | --- |
| Пул 50 позиций, ссылки, предложенная категория | `docs/imports/rb-first-50-fill-from-1c.xlsx` |

## Что в порядке

- **Технические атрибуты полны.** У всех 50 заполнены `VOLTAGE`,
  `AMPERNOST_AH`, `TEHNOLOGY`; также присутствуют `KHIMICHESKIY_SOSTAV` и
  габариты `RAZMER_NEW`. Пропусков — ноль. Это готовая база для фильтров и
  атрибутных посадочных.
- **Изображения есть у всех 50** (`preview` и/или `detail`).
- **Категоризация в источнике непротиворечива**: ровно два раздела, оба —
  ветки `akkumulyatory/dlya_ibp`, сирот и мульти-родителей нет.
- **Бренд восстанавливается достоверно** (см. P2-1): справочник даёт
  APC/Alarm Force/B.B. Battery/MNB без пропусков.

## Находки

Всего 290 находок по 50 товарам.

### P0-1 — описания шаблонные, а не авторские (42 из 50)

Тексты собраны из одного каркаса с подстановкой бренда, вольтажа и ёмкости.
Скелет-нормализация (снятие тегов и чисел) даёт крупные кластеры: 20 товаров
делят один шаблон, ещё 9 — второй, далее 3 / 2 / 2 / 2. Оставшиеся 8 отличаются
лишь вариантом того же каркаса.

Пример общего фрагмента: «Аккумулятор создан по технологии …, которая позволяет
выдавать стабильное напряжение при большой емкости… Аккумуляторы поставляются в
картонной упаковке по 1 штуке.»

Следствие: **это не «подтверждённые описания производителя»**. Для новых
индексируемых страниц такой текст — источник риска тонкого/дублирующего
контента и не может считаться выполнением критерия «реальный коммерческий
контент» Части 5. Требуется отдельный источник (даташит/сайт производителя)
и процесс подтверждения — черновой каркас для этого уже есть
(`ProductDescriptionDraft`, `docs/product-description-draft-workflow.md`).

### P1-1 — URL ни у одного товара не подтверждён (50 из 50)

`url_candidate_status = requires_url_registry_match` для всех. Ссылки вида
`/catalog/akkumulyatory/dlya_ibp/agm/<id>/` остаются кандидатами: сверка с
реестром legacy URL и решение по канонику/301 не выполнены. До этого решения
публиковать карточки нельзя — иначе возникнут дубли к живому Bitrix.

### P1-2 — описания содержат ссылки на старые Bitrix-URL (50 из 50)

Внутри `DETAIL_TEXT` — `href="/catalog/akkumulyatory/…"` (бренд, вольтаж,
технология). При переносе как есть они либо ведут в никуда на новом сайте, либо
тянут пользователя на старый. Нужен прогон через карту 301/реестр URL, а не
копирование текста.

### P2-1 — бренд хранится как ссылка на элемент (50 из 50)

Свойство `BRAND` (ID 360) содержит числовой ID (`4656`), а не название.
Экстрактор выгружает его без резолва. Справочник разрешает связь однозначно:

| ID | Бренд | Позиций |
| --- | --- | ---: |
| 20089 | APC | 41 |
| 4609 | Alarm Force | 6 |
| 4613 | B.B. Battery | 2 |
| 4656 | MNB | 1 |

Действие: добавить резолв в экстрактор. Это единственная находка, закрываемая
целиком автоматически и без внешних данных.

### P2-2 — несбалансированная HTML-разметка (48 из 50)

Число `<p>` не совпадает с `</p>` (типично `<p>` открыт повторно без закрытия).
Прямая вставка в новый шаблон даст поехавшую вёрстку — нужна санация HTML.

### P2-3 — цена и наличие в пуле не являются живыми (50 из 50)

Колонки «Цена BYN» и «В наличии» взяты из бэкапа Bitrix (состояние на дату
копии). По правилу честности данных они не могут стать ценой/наличием на витрине:
допустимы только `price_on_request` / `availability_on_request` либо вручную
подтверждённое значение с отметкой времени и автором.

### P1-3 — предложенная категория грубее фактической (50 из 50)

В пуле для всех 50 предложено `akb-dlya-ibp`, тогда как источник различает
**AGM (42)** и **GEL (8)**. Схлопывание теряет признак, который в текущем
каталоге уже работает и как фильтр, и как посадочная. Рекомендация: держать
технологию структурным атрибутом (`TEHNOLOGY`), а индексируемость AGM/GEL
решать отдельно по спросу — согласно правилу PLAN.md «таксономия отдельно от
SEO-посадочных».

## Что блокирует публикацию

1. Нет подтверждённых SKU/MPN в git-воспроизводимом виде (решения — в БД).
2. URL не сверены с реестром legacy: нет канона и 301.
3. Описания шаблонные — нужен подтверждённый источник.
4. Цена и наличие недостоверны — только honest-состояния.

Ни один пункт не закрывается автоматически без внешнего решения владельца,
кроме резолва бренда (P2-1) и санации HTML (P2-2).

## Влияние на готовность

Готовность **не повышается** и остаётся **43,8%**. Аудит — это доказательство
состояния, а не поставленный критерий: по правилу доказательств Части 5
засчитываются только одобренные товары, реальный сайт, лид и cutover.
Практическая ценность — вскрыт риск: если бы 23 товара опубликовали «как есть»,
на витрину попали бы шаблонные тексты, неподтверждённые URL и устаревшие цены.

## Следующие безопасные шаги

1. Выгрузить реальные 23 (`catalog:export-approved-identities`) и свести с этим
   аудитом — тогда область сузится с 50 до 23 без потери покрытия.
2. Закрыть P2-1 (резолв бренда) и P2-2 (санация HTML) в экстракторе/импортёре.
3. Сверить 50 URL с реестром legacy и зафиксировать канон + 301.
4. Завести описания через `ProductDescriptionDraft` с указанием источника
   производителя; шаблонный текст в новые карточки не переносить.
